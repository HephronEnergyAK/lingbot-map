Reconstruction

Save the target .blend, choose a Capture Source, select a qualified Profile, and start Reconstruction. The immutable JobSpec freezes the target file, Scene UUID, Timeline Start, source identity, model identities, and settings. Later draft edits do not retarget a running Job.

The separate Worker processes every presentation frame with bounded queues, writes structured progress and heartbeat files, and may continue to completion after Blender closes. It does not run inference inside Blender.

Preflight

Preflight decodes and validates the complete selected track without retaining pixels. It obtains exact frame timestamps, color/orientation facts, classification, and the full source checksum. Reconstruction rechecks source size and modification time and recomputes the checksum before Result publication.

Cancellation and interruption

Cancel writes a one-way request. The Worker checks it at bounded decode, inference, alignment, and checksum seams. After the grace period Blender force-terminates only the exact still-matching process identity. A dead Worker is never resumed; staging moves to diagnostics and a new Job can reuse copied settings.

Explicit sleep, hibernation, restart, or shutdown remains allowed. A still-live Worker may continue after resume only after sleep-request, CUDA, memory, disk, and source checks pass.

Long Capture Sources

Up to 320 frames uses one short inference window. Longer sources use overlapping bounded windows with explicit alignment, confidence-based ownership, and seam Quality Warnings. Version one supports at most 25,000 frames and never samples, drops, or duplicates presentation frames.

No explicit Loop Closure

Version one has no loop detector, pose graph, bundle adjustment, or global trajectory optimization. The model may produce a visually closed path for some captures, but this is not a guaranteed Loop Closure feature. The Extension never forces the final camera to the first or silently deforms points.
