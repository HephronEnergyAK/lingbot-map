穩定 error codes

穩定 codes 與 machine contracts 在所有語言中都維持不變英文。Localized UI 可以解釋它們，但不得翻譯 code。請在要求支援時提供完全相同的 code 與預設遮蔽敏感資料的可攜式診斷報告。

設定錯誤

setup.runtime.failed 表示不可變執行環境建構或驗證失敗。setup.runtime.cancelled 表示明確設定已取消且 staging 已保留。setup.model.checksum-mismatch 表示模型位元組與目錄識別不符。請檢查主機支援、Blender Online Access 或離線 cache 完整性、可用磁碟空間及確切模型來源。

啟動與 Pipeline 錯誤

launch.worker.failed 與 launch.worker.bootstrap-failed 識別正常 Worker status 前的失敗。pipeline.preflight.failed 表示完整媒體驗證失敗。pipeline.reconstruction.failed 識別重建失敗；請檢查其 phase、traceback、source identity、GPU 狀態、記憶體、磁碟及 structured warnings。

匯入與生命週期錯誤

import.transaction.failed 表示匯入在 commit 前停止，且唯一 staging datablocks 已移除。lifecycle.plan.failed 表示 ownership 或 preflight planning 無法證明磁碟操作安全。診斷匯出 codes（如 diagnostic-export-linked-file、diagnostic-export-race 及 diagnostic-export-file-too-large）會刻意 fail closed。

疑難排解清單

  1. 確認 Windows 11 x64、Blender 5.2 LTS、已選實體 GPU UUID、執行環境與模型為 Ready，以及設定檔通過驗證。
  2. 儲存目標 .blend；在開始或刪除工作前先解決重複的場景 ID 或匯入識別。
  3. 使用支援且未剪輯的 rectilinear MP4/MOV，並在任何來源變更後重新執行預檢。
  4. 保留足夠實體記憶體、VRAM 與專案磁碟餘裕。若驗證回報 GPU Busy，請關閉無關 GPU 使用者。
  5. 不要編輯進行中的 .jobs、Result、診斷或垃圾桶檔案。使用明確重新連結、復原與重試操作。
  6. 匯出已遮蔽敏感資料的報告。只有在收件者與傳輸皆可信任時，才選擇包含未遮蔽識別資料。
